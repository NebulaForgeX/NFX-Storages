# Error codes and i18n (translations)

This directory holds centralized error definitions and a small i18n system for the frontend.

- **`src/`** – Go packages per module (`sys`, `storages`). Each file defines `var ErrXxx = errx.XXX(...)`.
- **`src/storages/`** – object-storage / IAM / S3 domain codes (not a News leftover).
- **`src/sys/`** – shared infra codes (token, Kafka, Postgres, …).
- **`langs/`** – Generated JSON files per language (`en.json`, `zh.json`, `fr.json`). Generated by `cmd/gen_langs/`.
- **`cmd/gen_langs/`** – Script that scans `src/**/*.go`, parses the translation block in `/* ... */` comments, and writes `langs/<lang>.json`.

---

## How to write the translation block (`/* ... */`)

Each error **code** (the string passed to `errx.*`, e.g. `"STORAGES_BUCKET_NOT_FOUND"`) must have a corresponding **translation block** in a block comment at the **bottom** of the same `.go` file.

### Format

1. Use a **single** block comment: `/* ... */`.
2. For each code, add:
   - One line: **`!CODE_STRING`** (the exact constant value, no quotes).
   - One or more lines: **`*<lang><text>`** where `<lang>` is a language code (e.g. `en`, `zh`, `fr`) and `<text>` is the message inside `<` and `>`.

### Rules

- **`!CODE`** – Must match the `CodeXxx = "CODE"` value in the same file. One line per code.
- **`*lang<message>`** – Language line. `lang` is 2+ lowercase letters; the message is everything between `<` and `>`. You can add any languages (e.g. `en`, `zh`, `fr`).
- Blank lines between entries are allowed and improve readability.
- The block is usually placed at the **end of the file** after `var (...)`.

### Example

```go
var (
	ErrBucketNotFound = errx.NotFound("STORAGES_BUCKET_NOT_FOUND", "bucket not found")
	ErrAccessDenied   = errx.Forbidden("STORAGES_ACCESS_DENIED", "access denied")
)

/*
!STORAGES_BUCKET_NOT_FOUND
*en<Bucket not found>
*zh<存储桶不存在>
*fr<Bucket introuvable>

!STORAGES_ACCESS_DENIED
*en<Access denied>
*zh<拒绝访问>
*fr<Accès refusé>
*/
```

### Notes

- **Order**: List each `!CODE` once; all its `*lang<...>` lines must follow before the next `!CODE`.
- **Generation**: Run `task errors:gen-langs` (or `go run ./errors/cmd/gen_langs/ ./errors`). It clears `langs/`, then scans all `src/**/*.go` and merges every block into `langs/en.json`, `langs/zh.json`, etc.
- **New codes**: When you add a new `CodeXxx = "NEW_CODE"`, add a matching `!NEW_CODE` and at least `*en<...>` (and optionally `*zh<...>`, `*fr<...>`) in the same file’s block comment.
